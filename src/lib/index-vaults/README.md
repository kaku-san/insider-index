# Native index vault integration — full cycle (fail closed)

The September 14, 2026 revision-3 contract handoff selects **one existing Symmetry V3 vault and one native share mint per index**. This implementation does not deploy a program, mint a wrapper, custody assets in a service wallet, or maintain an ownership ledger. Investor actions require their own authorization; holders never sign native fund rebalances. Creation and naming belong only to the deployer.

## Private native cycle — implemented, not activated

`cycle-runner.ts` coordinates definition-driven owner/keeper preparation, durable signature-before-relay, finalized receipt accounting, cancellation and attributable-credit USDC conversion. `cycle-store.ts` uses migration `202609200001`; an unreadable journal, held lease, missing history or ambiguous send never licenses replacement funding/burn. Expiry requires consecutive finalized block evidence, not elapsed time. `cycle-observer.ts` reconciles canonical backing, all investor liabilities and native/SPL supply; support WSOL is not ignored.

`tests/cycle-prepare.test.mts` runs the controller and actual SQL against deployed-program **offline** fixtures: seven real CLMM acquisitions, 100 USDC → 99 raw shares → 99.513128 USDC, preserving unrelated owner/keeper inventory. These mixed-slot fixtures and synthetic finality headers are **not live finalized receipts**. Other definitions have independent prerequisite/identity regressions, not live or full-program cycle proof. Only proved CLMM shapes are admitted; unavailable legs block the whole definition.

Browser-safe parsers and `src/lib/frontend/cycle-history.ts` independently audit finalized operation history. Owner memos bind the policy/operation; they are provenance, never balances or receipt tokens. History includes canonical ATAs to catch external/issuer disposal; incoming purchases cannot replenish consumed credits. `notBeforeSlot` is the approved history anchor. `src/lib/frontend/cycle-wallet.ts` independently rebuilds owner instructions from policy/native state, checks backing and canonical recipients/debits/minima, scans history and actually simulates before signing. `POST /api/vaults/cycle` requires a short owner-message-signed session bound to origin/operation/policy; client-supplied policies, credits and keeper actions are rejected. Both are exercised in the local controller test. Empty operator policy/auth configuration disables the endpoint. The private `/kaku-admin` owner controls use explicit access-message and transaction signatures; `npm run keeper:cycle` is dry-run by default, with `--execute --keypair /absolute/external/path --watch` only on the separately authorized operator machine. Neither has been exercised with a real wallet/funds. See [the operator runbook](../../../docs/private-native-cycle.md) for exact approvals, configuration, interrupted-operation recovery and evidence limits.

Public funds, Invest Sign and public exit remain disabled. No live amount, fees/bounty budgets, keeper custody/funding/signing authority, exact native fee schedule or native economic/risk acceptance is implied by test policies. Native mint has no atomic minimum-share argument; filler surplus has no atomic maximum-output cap; an aggregate exit quote is not an atomic all-transactions USDC guarantee. Quantization, retained native residual backing and issuer/permissionless-settlement risks remain explicit activation approvals. No losslessness or exhaustive-edge-case claim is made.

## Public deposit rail — release-gated

The public Mag7 modal uses `POST /api/indexes/idx-theme-mag7-caucus/deposit/prepare`: a connected wallet supplies USDC through SDK `buyVaultTx` plus `lockDepositsTx`, which are compacted into one atomic user-signed transaction for a first depositor. The route reads the persisted vault definition and requires mainnet, a created vault/share mint, the per-vault deposit gate, and `VAULT_RELEASE.publicFundsEnabled`. First-time setup may include only the buyer's expected share/USDC/WSOL ATAs and a matched buyer-to-WSOL-ATA wrap; all ancillary accounts, programs, and Symmetry setup instructions are independently constrained, and unknown ancillary programs fail closed. It has no cycle policy, access message, journal, recovery, or cash-out path. A keeper mints shares later; signing a deposit is not a completed share receipt. The retained public-cycle endpoint is not mounted on Invest.

## Full cycle contract

[`full-cycle.ts`](full-cycle.ts) owns create → zap-in → mint → keeper rebalance → USDC zap-out. Every stage is testable and **fails closed until that stage has a matching receipt**. Public Invest Sign stays off (`VAULT_RELEASE.publicInvestSign === false`) until then. Preview quotes are estimated, not guaranteed. Unused USDC is returned on the way in; exit is USDC only (host 25 bps in / 0 out). Vault legs are catalog tokens: xStock preferred, verified Backpack `.US` when there is no xStock, never invented DEX lookalikes (`vault-legs.ts`). Native `update_token_prices` remains Raydium-only; zap/eligibility quotes are Raydium first, Jupiter if no pool, never Pyth/Hermes. The SDK `isRebalanceRequired` helper is forbidden (it always opens Hermes). One vault per index; creation-time WSOL/USDC slots are converted to Raydium-only zero-target support/cash slots, with WSOL active and USDC inactive. Keeper is a dedicated hot wallet, not the deployer and not a Phantom click. Layout cap is 100 tokens; hundreds of names cannot be one vault — [`native-caps.ts`](native-caps.ts). Operator status: `npm run vault:cycle`.

A separately authorized devnet-only test created one vault and finalized a 0.1 SDK-USDC deposit that settled through the creation-time Pyth-type accounts; the vault's oracles were then switched to **Raydium CPMM only** and a second 0.1 SDK-USDC deposit completed deposit → lock → Raydium `update_prices` → mint → claim with zero Hermes/Pyth, using [`devnet-settle.ts`](devnet-settle.ts) (`npm run vault:settle:devnet`, [procedure](../../../docs/devnet-vault-settle.md)). Person/index research surfaces may mount only the release-gated native preparation flow for a published vault; the existing devnet test vault is not implicitly exposed. Preparation returns `503`/`wait` with no transactions when native readiness is missing. A separate [native redemption preflight](../../../docs/devnet-vault-redeem.md) observes that vault and validates the SDK sell encoding, but always stops without signing or broadcast. No broadcast route exists. The public deposit prepare route returns user-signed contribution and lock transactions only after its persisted-definition and release checks. It does not certify their confirmation or mint shares; a keeper performs later minting. Native-USDC exit, optional wallet conversion, automatic signing and native recovery actions remain disabled. There is no environment variable that silently enables them. The native settlement/share-transfer/redemption/fee roundtrip is **NOT_RUN**, not PASS. This is integration infrastructure, not a launch-ready or audited vault.

Legacy `/api/indexes/quote` and `/api/indexes/execute` return `503` without payloads/signatures. The old `STUBIDX`/in-memory index position writer is removed. Index pages display model allocations separately from unavailable actual native holdings. Existing single-trade Jupiter execution and full disclosed books remain separate and intact.

### Storage/recovery limits

**Wallet-signed create drafts** (`index-vault-create.ts`, `kaku-san-create.ts`) do not use the local file journal: on a serverless/Vercel host the filesystem is read-only except `/tmp`, and `/tmp` is neither durable nor shared across invocations. They use `create-draft-store.ts` — one Supabase row per index id (migration `202609190001`), written through service-role security-definer RPCs in the style of `set_insiderindex_vault_address`. The row holds the unsigned create transaction bytes and identity (never key material or signed spending payloads) and enforces the same properties: one draft per index (primary key), an exclusive writer lease whose loser fails closed rather than racing, writes fenced on the caller's lease token, and a `submitted` latch that is monotonic in the store (only `clear`, on discard, resets it; the discard RPC refuses while it is true). An unreadable or unwritable journal THROWS, so the create path refuses rather than proceeding unjournaled. A lease left held by a crashed writer is **RECOVERY_REQUIRED**, never stolen on a timer: release it by hand with `select public.recover_insiderindex_vault_create_draft_lock('<index-id>', '<lock-token>')` (the token is in the next error message and in the row's `lock_token`).

**Diagnostic/observation journals** (`operations.ts`, `registry.ts`, `deployer.ts`, the keeper workers) remain private atomic JSON snapshots on **one durable local host**, fsynced and serialized by an exclusive directory lock, under `.data/index-vaults/` (already ignored and outside the web root). They persist workflow observations, never signed spending payloads or secret bytes. Concurrent writers fail closed; a crashed `.lock` is **RECOVERY_REQUIRED**, not an automatically stolen lease. Inspect processes and prior signatures/state before deliberate lock recovery. No broadcast route exists while this recovery is manual.

Before distributed/unattended execution, replace the remaining local diagnostic journals with transactional shared storage, uniqueness constraints and fenced leases. Do not deploy those journals on ephemeral/serverless disks. Native state remains authoritative. Readiness/config changes invalidate preparation, not ownership. Old generations and outstanding claims must remain discoverable.

## SDK/source inspection

Pinned runtime dependencies: `@symmetry-hq/sdk@1.0.22`, `@solana/web3.js@1.98.4`, `@solana/spl-token@0.4.14`; exact npm integrity is in `package-lock.json` and `evidence/vaults/sdk-report.json`.

The SDK package identifies itself as **Symmetry V3** and is BUSL-1.1, with an Additional Use Grant explicitly permitting commercial Symmetry integration, not competing protocol/SDK infrastructure. No closed program source or SDK code is vendored. It ships typed binary layouts, **no standalone Anchor IDL JSON**. We record types/layout hashes, never relabel one as an IDL hash. This does not attest deployed binary/source correspondence.

Observed distributed-SDK details:

- Program constant (both networks): `BASKT7aKd8n7ibpUbwLP3Wiyxyi3yoiXsxBk4Hpumate`.
- Devnet SDK USDC is `USDCoctVLVnvTXBEuP9s8hntucdJokbo17RwHuNXemT`, not an assumed mainnet mint; no stock-route compatibility is inferred.
- `buyVaultTx` implementation emits **create + contribution** batches; its comment describes a lock batch which is commented out in this distribution. Use separate `lockDepositsTx` after confirmed creation/contribution, never assume the comment proves lock.
- Amount fields are raw integer **numbers**, not display units. SDK internals also convert some native counters/bounty balances with `parseInt`; large internal amounts need independent policy validation before any wallet release.
- `createVaultTx` derives addresses from the current native vault counter; persist returned vault and mint separately. Global-counter races and uncertain create receipts require reconciliation, not generation of a second vault.
- `updateTokenPricesTx` always constructs a Hermes client and requests Pyth price updates, even when the vault has zero Pyth oracles; the Raydium-only path builds `updateTokenPricesIx` directly instead. The instruction layout carries two fixed WSOL/USDC custody reference accounts as program constants; they are not vault oracles and are never updated here.

- `sellVaultTx` has `keep_tokens`, no documented output-mint or aggregate minimum-USDC argument. Keep all allocated slots for baseline redemption; reconcile residuals and correct-program recipient ATAs before enabling claims.
- `signAndSend*`/SDK `simulateTransactions` helpers can send. Read-only connection middleware rejects non-read RPC methods, including send/airdrop. The scripts never load a signer.

`npm audit` currently reports transitive advisories (including bigint-buffer, axios, ws). The pinned SDK/SPL tree has no nonbreaking fix for every advisory; funds remain disabled. No blind audit-force downgrade or silent SDK upgrade was made. Review these before financial release.

## Person index mapping (top-20 FMP annual holdings)

The book is the **latest FMP annual holdings** (position-value midpoints) from the captain drop, committed verbatim (holdings not truncated) at `data/insiderindex-source-buckets/pelositracker-fmp-latest-top20/` and versioned by the source zip `sha256` in its `MANIFEST.json`. Refresh the bucket with `npm run fmp:holdings:bucket -- --source <unzipped-drop> --sha <zip-sha256>`. This is a separate consumer/book from the person-pages task's PelosiTracker positions handoff (`src/lib/tracker/`); do not re-parse or re-wire that bundle here.

- `person-index-map.ts` (pure): per person derives the ticker set, the weight basis (annual holding value midpoint), and the resolved Solana leg per ticker in the fixed order **xStock → verified Backpack `.US` → unmapped** via the Solana catalog's `preferredToken`. Every mapped leg carries the exact catalog mint and its evidence; a mint is only ever the catalog's own, never guessed and never a lookalike/similar ticker (GOOG ≠ GOOGL). Unmapped is first-class: `coverage.unmappedByWeightBps` discloses the dropped share; weights renormalise across mapped legs only, never silently around an unmapped leg. Transaction-derived books (`bookSource: txn-derived`) are activity, never weights — they stay `BLOCKED`. An annual book with no ticker rows is a separately-recorded gap (`no-ticker-holdings-in-annual-book`). Duplicate-underlying guard: two legs that resolve to the SAME company via a curated share-class pair (`share-classes.ts`, e.g. Alphabet's GOOGL + GOOG) are collapsed into one leg deliberately — the tradable/xStock survivor keeps the merged weight, the duplicate is dropped, and the collapse is recorded on `provenance.collapsedShareClasses` so it is never silent.
- `pool-evidence.ts`: pluggable per-mint Raydium pool source. `map-top20-index-vaults.mts` now adopts the landed `raydium-pools-mainnet` snapshot via `poolSourceFromReadiness(poolReadiness, meta)`; `PENDING_POOL_SOURCE` remains only for tests/fixtures. ## Parallel FMP handoff

`composition.ts` consumes a **published ModelComposition execution envelope** with immutable source, manifest and policy hashes. `consumePublishedComposition` rejects partial/stale/unpublished input and names execution-test data `Execution Test — not politician holdings` under an `execution-test-*` identity. Until that store publishes a compatible envelope, callers inject labelled test models; no real FMP portfolio or active strategy is asserted. No stock mints are hand-added.
